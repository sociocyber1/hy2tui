
# hy2tui

Консольный клиент **Hysteria2** с режимом **TUN**: весь трафик системы идёт через VPN, как в nekoray.
Дашборд в стиле btop: графики скорости и пакетов, живой список соединений с доменами и
приложениями, лог DNS-запросов, задержка, внешний IP, анимации.

## Прокси для браузера: 127.0.0.1:2080

hy2tui открывает **смешанный порт SOCKS5 + HTTP** на `127.0.0.1:2080`, как nekoray:
один порт понимает оба протокола, поэтому настройки Firefox из nekoray подходят без изменений.

Три режима, переключение клавишей **`m`** на экране профилей:

| Режим | Что идёт через VPN | Нужен root |
|---|---|---|
| **TUN + прокси** (по умолчанию) | вся система + браузеры через 2080 | да (`sudo`) |
| **Только прокси** | только программы, настроенные на 2080 | **нет** |
| **Только TUN** | вся система | да |

```bash
hy2tui --proxy-only     # включить режим «только прокси» и запустить без sudo
```

**Firefox** → Настройки → Сеть → Параметры:
- *Ручная настройка*, **SOCKS-узел `127.0.0.1`, порт `2080`, SOCKS v5**
- ✔ **«Отправлять DNS-запросы через прокси при использовании SOCKS v5»**: домены резолвятся на
  сервере, без утечек и без подмены DNS провайдером
- поле HTTP-прокси можно оставить пустым. Если заполняете его (`127.0.0.1:2080`), отметьте
  «Также использовать этот прокси для HTTPS»

**Chromium / Chrome:** `chromium --proxy-server="socks5://127.0.0.1:2080"`
**curl:** `curl -x socks5h://127.0.0.1:2080 https://ifconfig.me`

Соединения браузера видны во вкладке «Соединения» с пометкой `SOCK`/`HTTP`, с доменом и
приложением (firefox, chromium…). Трафик прокси учитывается в графиках скорости.
Адрес меняется в `~/.config/hy2tui/config.toml`: `proxy = "127.0.0.1:2080"` (пусто = выключен).

## Ядро встроено в hy2tui

Официальное ядро hysteria (v2.14.0, сжатое xz) **уже внутри бинарника hy2tui** — для x86_64
(обычная сборка и быстрая `-avx`) и arm64. При первом запуске оно распаковывается в
`~/.local/share/hy2tui/bin/hysteria` за ~1 с и проверяется по SHA-256 из официального релиза.
Интернет и доступ к GitHub для этого **не нужны**.

```bash
hy2tui install-core --embedded   # переустановить встроенное ядро
hy2tui install-core              # скачать более новое с GitHub (если доступен)
```

Если скачивание не удалось (GitHub заблокирован), hy2tui подскажет `--embedded`.
Обновить встроенное ядро для следующей сборки: `vendor/update-core.sh` (можно с `PROXY=…`),
затем `cargo build --release`. Без файлов в `vendor/` hy2tui тоже соберётся — тогда ядро
будет скачиваться, как раньше.

## Как устроено

* **hy2tui** (Rust) — интерфейс, профили, маршруты, DNS, статистика, перезапуск при обрыве.
* **hysteria** — официальное ядро Hysteria2 (Go, apernet/hysteria). Оно делает QUIC,
  Salamander-обфускацию, Brutal/BBR и TUN. hy2tui само скачивает его с GitHub
  (докачка при обрыве, проверка SHA-256). На CPU с AVX2 берётся более быстрая сборка `-avx`.

## Почему быстрее nekoray

| Что | nekoray (часто) | hy2tui |
|---|---|---|
| UDP-буферы (`rmem_max/wmem_max`) | стандартные ~208 KiB → QUIC упирается в потолок | поднимаются до 16 MiB при подключении |
| Контроль перегрузки | обычно BBR (скорость канала не указана) | **Brutal**, если задать скорость (`b`) |
| TUN | отдельный стек sing-box (gvisor) поверх ядра | TUN самого ядра hysteria, без лишнего слоя |
| Ядро | общая сборка | сборка `amd64-avx`, если CPU её тянет |

**Самое важное — нажми `b` на профиле и укажи реальную скорость своего интернета**
(например `50 200` = 50 Мбит/с отдача, 200 Мбит/с приём). Не завышай: слишком большое значение
только забьёт канал потерями.

## Установка (Artix / Arch)

```bash
sudo pacman -S --needed rust curl wl-clipboard   # xclip — если у тебя X11
cd hy2tui
cargo build --release
sudo install -m755 target/release/hy2tui /usr/local/bin/
# ядро hysteria уже встроено — скачивать ничего не нужно
```

### Скачивание ядра (`install-core`)

```bash
hy2tui install-core                 # 8 параллельных потоков
hy2tui install-core -j 16           # больше потоков на плохом канале
hy2tui install-core --proxy socks5h://127.0.0.1:1080
hy2tui install-core --force         # перекачать, даже если версия та же
```

* Файл режется на куски, несколько async-потоков (tokio + reqwest) качают их одновременно;
  быстрое соединение просто берёт больше кусков.
* **Обрыв не сбрасывает прогресс.** Каждый байт пишется сразу на своё место в `hysteria.download.part`,
  прогресс сохраняется в `.state` два раза в секунду. Поток, который 20 с ничего не получает,
  переподключается и продолжает свой кусок. Если пропал весь интернет — ждёт (2…30 с) и продолжает.
* Ctrl+C, выключение ПК, `kill` — просто запусти команду снова: `resuming: 15.7 MiB of 24.0 MiB`.
* Качается конкретная версия (`download/app/v2.x.y/...`), поэтому докачка никогда не склеит
  куски двух разных релизов. В конце — проверка SHA-256 по `hashes.txt` релиза.
* Если уже стоит последняя версия — ничего не качает.

## Использование

```bash
# 1. скопируй ссылку hy2://…  в буфер
hy2tui add                   # добавит из буфера (или: hy2tui add 'hy2://…')
hy2tui                       # откроет интерфейс (попросит sudo: TUN требует root)
hy2tui connect               # сразу подключиться к последнему профилю
hy2tui connect 2             # к профилю №2
```

В интерфейсе можно вставлять ссылки прямо в окно: **Ctrl+Shift+V** — профиль добавится сразу.
Можно вставить сразу несколько ссылок.

### Клавиши

**Профили:** `Enter` подключить · `v` вставить из буфера · `a` ввести вручную · `b` скорость ·
`r` переименовать · `d` удалить · `x` отключить · `D` DNS-серверы · `Tab` дашборд · `q` выход

**Дашборд:** `1` обзор · `2` соединения · `3` DNS · `4` лог (или `←` `→`) · `x` отключить · `D` DNS-серверы ·
`r` переподключить · `i` обновить внешний IP · `↑↓ PgUp PgDn` прокрутка · `End` к последним ·
`o` только открытые соединения · `C` очистить таблицу · `?` помощь

### Что показывает дашборд

| Вкладка | Что там |
|---|---|
| **1 Обзор** | графики приёма/отдачи (braille, как в btop), анимированная линия потока (стрелки бегут быстрее при большем трафике), пакеты/с вход/выход + ошибки/дропы TUN, задержка с историей, CPU/RAM ядра, открытые TCP/UDP, новые соединения/с, DNS-статистика, живая лента соединений, топ доменов |
| **2 Соединения** | таблица: время · TCP/UDP · **приложение** (firefox, telegram…) · IP:порт · **домен** · длительность · открыто/закрыто/ошибка |
| **3 DNS** | каждый DNS-запрос: домен, тип (A/AAAA/HTTPS…), ответ, время ответа, статус (NOERROR/NXDOMAIN/…) |
| **4 Лог** | лог ядра и hy2tui |

Откуда данные:
* соединения — события ядра `TUN TCP request / closed / error` (ядро запускается с `debug`-логом);
* домены — встроенный DNS-форвардер hy2tui на `127.0.53.53:53` (UDP и TCP): он пересылает запросы
  на `1.1.1.1/8.8.8.8` **через туннель**, записывает ответы и сопоставляет IP → домен;
* приложение — по порту соединения через `/proc/net/*` и `/proc/<pid>/fd` (как `ss -p`);
* пакеты/байты — счётчики интерфейса `/sys/class/net/hytun/statistics`.

Для UDP ядро сообщает только локальный адрес, поэтому у UDP-сессий нет адреса назначения.

`q` и `Ctrl+C` всегда отключают VPN корректно: ядро останавливается, DNS и sysctl возвращаются.

## Что происходит при подключении

1. Адрес сервера резолвится **до** включения VPN. Ядро подключается по IP (SNI остаётся доменом),
   поэтому переподключение не зависит от DNS.
2. IP сервера и локальные сети (192.168.x.x, 10.x и т.д.) исключаются из TUN — нет петли
   маршрутизации, локальная сеть и принтеры работают.
3. Маршруты: весь IPv4 (`0.0.0.0/0`) и глобальный IPv6 (`2000::/3`) → интерфейс `hytun`.
4. `/etc/resolv.conf` временно указывает на встроенный DNS-логгер `127.0.53.53`, который пересылает
   запросы на `1.1.1.1, 8.8.8.8` — **через туннель**,
   без подмены DNS провайдером. Оригинал сохраняется в `/var/lib/hy2tui/` и возвращается при отключении.
   Если NetworkManager/dhcpcd перезапишет файл — hy2tui вернёт свой.
5. Если ядро упало или пропал интернет — автоматический перезапуск (2 → 4 → … → 30 с).

Если hy2tui убили через `kill -9`, ядро умрёт вместе с ним (PDEATHSIG), а DNS
вернётся при следующем запуске или командой `hy2tui restore`.

## Настройки

`~/.config/hy2tui/config.toml` (права 600 — там пароли). Меняй, пока hy2tui закрыт.

```toml
[settings]
override_dns = true          # DNS через туннель
dns = ["1.1.1.1", "8.8.8.8"]
bypass_lan = true            # локальная сеть мимо VPN
tun_name = "hytun"
mtu = 1500                   # можно попробовать 9000 — иногда быстрее
tune_sysctl = true           # большие UDP-буферы + rp_filter=2
fast_open = true             # минус один RTT на каждое соединение
auto_reconnect = true
exclude = ["203.0.113.0/24"] # что ещё пустить мимо VPN
core_path = ""               # свой путь к hysteria, пусто = авто
```

## DNS-серверы: свои, с приоритетом

Клавиша **`D`** на экране профилей или на дашборде открывает список DNS-серверов, которые
используются внутри туннеля (при `override_dns = true`, по умолчанию включено).

- **Порядок = приоритет.** Сначала спрашивается первый сервер, если он не ответил — следующий.
- `a` — добавить: IP-адрес (IPv4/IPv6), несколько через пробел или запятую, либо имя
  провайдера: `cloudflare`, `google`, `quad9`, `adguard`, `opendns`. Новые ставятся в конец.
- `K` / `J` (или `+` / `-`, Shift+↑/↓) — поднять или опустить выбранный сервер.
- `d` — удалить. **Последний сервер удалить нельзя**, чтобы DNS не сломался.
- `r` `r` (два раза) — сбросить к значениям по умолчанию: `1.1.1.1`, `8.8.8.8`.
- `t` — тест скорости твоих серверов: время ответа в мс (через туннель, если подключены).
- `b` — тест **всех** провайдеров сразу, от быстрого к медленному; `f` — взять два самых быстрых.

Провайдеры для быстрого добавления (все отвечают на обычный DNS, порт 53):
`cloudflare`, `google`, `quad9` (некоммерческий, без логов IP), `dnssb` (без логов, без фильтров),
`uncensored` (UncensoredDNS, Дания: без цензуры и логов), `dns4eu` (европейский, без фильтров),
`adguard` (режет рекламу), `opendns`. LibreDNS и Mullvad DNS работают только через DoH/DoT,
поэтому здесь их нет.

**Скорость.** Ответы кешируются по TTL: повторные запросы отвечают за 0 мс. Каждый запрос идёт
сразу по UDP и по постоянному TCP-соединению (внутри туннеля это надёжный QUIC-поток).
Через 300 мс подключаются остальные серверы, и побеждает первый ответ. Потерянный UDP-пакет
больше не даёт таймаутов по 5–13 с.

Список сразу сохраняется в `~/.config/hy2tui/config.toml` (`dns = [...]`) и используется при
следующих запусках. Если VPN подключён, изменения применяются **на лету, без переподключения**.
Для доменов из notToVPN по-прежнему используется отдельный `direct_dns`.

## notToVPN: какие сайты не пускать через VPN

Работает в режиме TUN и **выключено по умолчанию**. Клавиши на экране профилей:
**`n`** — изменить список, **`N`** — включить/выключить.
В конфиге: `not_to_vpn`, `not_to_vpn_domains` (по умолчанию `ru, рф, su, by, kz, ua`) и `direct_dns`.

Как это работает:
- DNS-сервер hy2tui определяет адреса доменов из списка (целые зоны вроде `ru`, `kz` или
  отдельные домены вроде `gosuslugi.ru`) **напрямую** через `direct_dns` (Яндекс 77.88.8.8).
- Ещё до того, как приложение получит ответ, эти IP получают правило
  `ip rule … lookup main pref 8765`, и соединение идёт мимо туннеля.
- Всё остальное, включая остальные DNS-запросы, остаётся в VPN. Во вкладке DNS прямые запросы
  помечены `⇢`. Правила удаляются при отключении и после сбоев.
- Ограничения: сайты с тем же IP (большие CDN) тоже пойдут напрямую, а программы, которые
  подключаются по IP без DNS, не распознаются. Нужен `override_dns = true`.

## Автоматическое восстановление сети

При **каждом запуске** (с sudo) hy2tui сам убирает то, что могли оставить сбой или закрытый
**CyberVPN**: возвращает исходный `/etc/resolv.conf` (из своих резервных копий и копий CyberVPN,
в правильном порядке), удаляет оставшиеся TUN-интерфейсы (`hytun`, `cybervpn`) и устаревшие
правила маршрутизации (таблица 2022). Пока работает любое VPN-ядро, сброс не выполняется.

Если **первое подключение не удалось** (`connect error: timeout`), hy2tui сам выполняет тот же
сброс и пробует ещё раз. Вручную: `hy2tui reset`.

hy2tui и CyberVPN не запускают TUN одновременно: второй сообщит, что первый уже работает.
В режиме «только прокси» их можно использовать вместе.

## Если что-то не так

* **Нет интернета после подключения** — смотри лог внизу дашборда. `wrong password` / таймаут =
  неверный пароль obfs или auth. После выхода всё возвращается само; если нет — `hy2tui restore`.
* **Медленно** — задай скорость `b`, попробуй `mtu = 9000`. Задержку видно в панели health.
* **Не работает вставка `v`** — поставь `wl-clipboard` (Wayland) или `xclip` (X11),
  либо просто вставляй Ctrl+Shift+V в терминал.
* **Firewall** (ufw/nftables) должен пропускать исходящий UDP на порт сервера.
